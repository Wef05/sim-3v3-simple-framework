# 队员时域避让

每帧先收集整队移动意图，再统一下发。优先级为固定守门员、距球最近的非守门员、其他队员；距离相同按编号，球不可见时按编号。优先级以本帧位置计算，与进攻角色的迟滞选择独立。

原有 A* 继续处理球门、按动作启用的球和对手。整队协调期间不再把队友永久固定在当前位置，而是用未来一秒的运动预测处理队友。将每名队员看作半径 TEAMMATE_RADIUS 的圆盘，中心最小间距为两个身体半径之和，加 TEAM_MOTION_MARGIN_M；默认 0.48 × 2 + 0.15 = 1.11 米。这是保守配置，尚未从仿真模型中实测身体包络。

冲突判定解析计算整个时间区间内相对位置的最小距离，因此能发现采样点之间的迎面碰撞，也允许不同时间经过同一交叉点。每帧重新计算，不保存旧路线预约。

依次尝试原速、减速、等待、低速侧移，联合搜索满足全部两两间距的组合。按优先级顺序搜索，只有低优先级队员的所有候选都不能让出安全空间时，才调整更高优先级队员。侧移仍检查本动作的静态障碍与场地边界。停止、罚下或未就绪的队员不会被自动驱动让路；其当前位置仍占据空间。初始重叠仅允许不再靠近并逐渐分离，无解时整队取消踢球并停止。物理上已无法避免的碰撞不能通过软件停车保证消除。

SDK 踢球带有自动接近动作，按向球移动预测并与队友检查；不安全时取消本帧踢球。该预测并非 SDK 内部轨迹的精确重现。运动采用短时匀速近似，未建模真实加减速、转向轨迹、摔倒后身体形状和控制延迟，需在实机或仿真中验证并调整预测窗口及误差余量。此功能是滚动时域局部协调，不是带时间节点的全局最优寻路；复杂死锁可能仍需更长时间范围的路线规划。

参数在 src/param.py：TEAMMATE_RADIUS、TEAM_MOTION_HORIZON_S、TEAM_MOTION_MARGIN_M、TEAM_YIELD_SPEED_M_S。入口为 runtime._tick 的 coordinated_motion，单独调用 Player 时保持原有行为。

验证：python3 -m unittest discover -s tests -q。新增测试覆盖同/异时交叉、迎面、身体体积、重叠脱离、守门员优先、最近球排序、静止占位、坐标转换、异常停车及 SDK 接近取消。未执行在线比赛。
