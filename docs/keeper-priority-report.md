# 门将紧急封堵优先级与近身解围连续性

## 范围与实现

用户批准的后续最小方案，沿用独立 worktree `keeper-block-continuity`、分支 `codex/keeper-block-continuity`，基线 `cdf1f3f`（含最新 MAIN `403d398`）。不改角色分配、守门区域、射门判断或核心架构。

- 导航预约按运动优先级及编号确定让行顺序。低优先级队友预约不再对门将施加额外 0.10 m 让行余量；实体半径、观测速度、停车假设、制动过程和最终队内冲突检查全部保留。
- 紧急直线封堵（现有 priority=100）与队友踢球接近走廊冲突时，明确将该队友本帧执行意图改为停车，先调用 release_kick，再下发门将动作。只替换执行层副本，不修改上游意图映射。普通走位不抢占踢球。
- 近身解围优先保留安全旧目标；旧目标失效时同帧尝试现有五个候选方向。安全替代方向存在则继续请求踢球，不重置 kick_since；无安全方向仍退出。距离、角度、速度、对手领先余量、射门封堵优先级和 1.2 s 超时不变。
- 看板增加阻挡者优先级、因封堵取消踢球、近身解围拒绝原因、旧目标失效及同帧重选原因。遥测格式向后兼容。
