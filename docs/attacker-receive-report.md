# Attacker 接球等待点与接近避球

## 行为与变更范围

基线 `aaee819`；worktree `/private/tmp/attacker-receive-first`；分支 `codex/attacker-receive-first`。主工作区已有修改未转入，Studio 自动更新的任务工作区配置不纳入提交。

原 attacker 在 2 m 内直接交给自动踢球，远处追赶球后点。现在普通接球先进入有安全间距的等待点，到位并稳定后才交接 SDK；补射仍可跳过拦球。最初实现把机器人中心直接送到预测球位，用户指出可能途中撞球后，按批准的修订方案改为以下行为。

- B 为补偿后的当前球位，I 为原始预测球位，T 为最终出球目标。非退化向量 `(I-B)·(T-B)<0` 才进入补射；严格 90° 或退化向量不判补射。判定不使用偏移后的等待点。
- 运动球等待点 `R = I + 0.60 * normalize(I-B)`。静止/未知速度/退化预测从机器人所在侧距当前球位 0.60 m 等待，避免穿球换侧。完全重合时沿机器人身后方向脱离。
- 普通接近及远距离补射接近均启用现有导航 `avoid_ball`，同时使用路径球障碍与预测球轨迹碰撞检查；到点误差 0.05 m。现有身体半径 0.25 m、球半径 0.11 m、路径余量 0.10 m，等待点留有额外余量，但不是物理碰撞绝对保证。
- 等待点跨帧保留。来球方向改变超过 30°、横向偏离超过 0.40 m、球已越过等待区域，或球停在另一个远离等待点的位置时重选，避免不断追着预测点跑。
- 到位后只面向来球，停止平移。观测和补偿球位均在 0.65 m 内、有效观测球速 ≤0.30 m/s、机器人观测平移速度 ≤0.15 m/s，并连续维持 0.15 s 新球观测，才进入自动踢球。重复快照不累计时间，未知球速不当静止。
- 补射在两种球位均不超过 2 m 时直接请求踢球；更远时沿现有球后 0.35 m 接近点避球行走。自动踢球保持至球超过 2.5 m；换角色/阶段、时间回退、超过 0.5 s 的决策间隔及无效观测清理记忆。
- 出球选点、力度、角色竞争及守门职责不变；结构阻挡无安全替代仍停车。近身低速和 `auto_kick` 仅表示策略判据/请求，不能证明 SDK 踢球成功；触球证据单独读取裁判事件。

修改文件：`src/utils/attacker_receiving.py`（独立状态逻辑）、`src/player.py`、`src/utils/ball_motion.py`、`src/param.py`、帧准备、遥测、看板与相应测试。看板记录原始拦球点、等待点、安全间距、角度、到位状态、机器人/球速、稳定时间和切换原因。旧回放无需接球字段，兼容读取。

## 实验设计与身份

两次测试均由用户分别授权：初版一次，安全间距修订版再一次。每次目标为裁判主时间减少 60 s；固定 600 s 赛制中主动结束，均不计完整自然比赛或胜率样本。对手官方 AI，随机种子未控制，单场条件不足以作统计对照。保留已有看板历史，每场按 session 和起止 ID 导出，不清空共享数据。

我方 `com.example.lqinternalmatch` 2.0.3，对方 `com.booster.default3v3ai`。Studio 指向本任务 worktree，通过正式入口构建部署，runner 双方 Active 后开赛。47 个 Python 文件逐一核验：46 个源码、构建包及部署摘要相同；仅顶层纯说明 `src/__init__.py` 被构建工具置空，包与部署一致。修订版实验与最终行为源码一致，见 [产物身份](attacker-receive-evidence/run02/artifact-identity.json) 和 [runner 日志](attacker-receive-evidence/run02/runner-preflight.log)。

初版的源码及类型声明补全差异独立保留于 run01；不将初版产物误作修订版。第二场用官方模拟器重置物理状态；裁判保留 finished，`/match/start` 重新创建本场并恢复 600 s。监控校验 `startedAtWallTime`，防止仅因固定 `local-match` ID 相同而混淆场次。
