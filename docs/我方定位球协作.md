# 我方定位球：设计与实现

目标：主罚者把球踢向接应者将要到达的空当，接应者在出球之前开始跑位。适用于开球、角球、球门球、界外球、直接和间接任意球；点球保持单人射门。

## 执行顺序

1. 只有裁判允许我方执行的 PLAYING 阶段才组织定位球；READY 继续按原逻辑站位，SET 停止。
2. 固定 1 号守门员留守。从已就绪、未受罚、位置已知的场上球员中选距球最近者主罚，其余场上球员接应。主罚者和接应者在本次定位球内锁定，角色不可用时取消旧命令并重选。
3. 按定位球类型生成多个场内候选点，排除传球线路或落点附近有对手/其他队友的点，再综合接应距离、落点与对手距离选择目标。目标保持稳定，线路被堵时才换点。
4. 接应者面向球、避球避人走向目标；主罚者先在球后约 0.8 米等待。接应者距目标不超过 0.6 米且线路畅通时，主罚者追近球并向目标传球。
5. 观测到球离起点至少 0.25 米后，主罚者停止踢球，接应者追球并转入进攻。裁判转入普通比赛后仍给接应者短暂优先权，最长至首次提交踢球指令后 3 秒；未记录出球时从阶段切换起算。之后恢复原有最近球员进攻。

这里的“接球”复用现有 `attack()` 追球射门控制，没有新增停球/控球动作。球移动只是交接信号，不等同于确认本方成功触球或传球成功。

## 各类定位球的接应方向

| 类型 | 候选空当 |
| --- | --- |
| 开球 | 左右横向，或略向后侧的短传点 |
| 角球 | 从角旗向场内、向后回传的点，避免默认直接射门 |
| 球门球 | 向前左右两侧及中央的出口 |
| 界外球 | 向场内斜前、斜后方 |
| 任意球 | 斜前方、横向及后侧备用点 |
| 点球 | 主罚者射门，另一名场上球员停止移动 |

坐标沿用项目既有约定：己方门在负 x，对方门在正 x；本改动不增加换边坐标变换。候选点距离场地边缘至少 0.65 米。所有分工均保留固定守门员，球门球也由场上队员主罚。

## 异常与兜底

- 球不可见：场上队员停止并取消踢球。
- 主罚者或接应者倒地、受罚、失去位置：取消不可行动球员的命令，由可行动球员重新组织。
- 只有一名场上队员：等待 6 秒后向畅通的场内空当出球，守门员不被拉入接应角色。
- 接应者未到位：6 秒后允许向畅通的目标空当出球。该兜底不保证队友能够追上。
- 所有候选路线被堵：持续找点并等待，不因超时强制踢入阻挡路线。这种情况下仍可能耗尽裁判窗口。
- 裁判停止、对方主罚、READY：清除本方定位球方案，使用既有对应处理。
- 进入新的我方开球/定位球阶段或定位球类型改变：创建新方案。若裁判没有阶段/类型变化就重置同类事件，目前无法可靠区分。

## 代码与参数

- `src/restart.py`：候选点、线路检查、角色锁定及准备/出球/接应过程。
- `src/main.py`：阶段路由、固定守门员分工、正常比赛接应交接。
- `src/player.py` 的 `pass_to()`：独立的指定目标传球接口。目标坐标用于实际踢球方向，并由已有 `kick()` 转换为身体坐标。距离球过远时先走位。
- `src/param.py` 的 `RESTART_*`：等待时间、到位阈值、线路间距、边界留白及传球力度。

定位球传球（含超时兜底）的出球参数固定为 1.0，不随距离变化。底层接口将此参数称为力度（power），不代表已验证的实际球速为 1 米/秒；路线检查也是当前帧几何检查，不预测对手拦截。

## 验证

运行 `python3 -m unittest discover -s tests -q`。当前 43 项通过，包含原守门员、对方定位球测试，以及新增跑位后传球、实际身体坐标出球方向、球移动后主罚者释放、被堵不强踢、超时兜底、接应者不可用、球丢失、阶段交接及候选点边界测试。

测试使用真实策略和 Player 计算、模拟机器人后端，未运行 Booster 实际仿真比赛。还需在仿真验证力度与传球距离、走位耗时、执行器连续指令行为，以及各类定位球的裁判规则；这些测试不证明成功率或无犯规。
