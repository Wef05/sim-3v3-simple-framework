## 实验设计与产物身份

一次 60 秒裁判计时短测，默认 600 秒赛制下由操作端主动结束，不纳入自然完赛胜率。目标是验证本任务部署、概率选择及意图记录；若没有满足阈值的场景，不宣称验证自动传球执行。保留原看板历史，以 session 和起止帧 ID 隔离。未控制随机种子，不进行胜率比较。

Studio 从本任务工作区构建并部署。模拟器打开至少 30 秒、双方 Active 且裁判 ready 后开赛。双方代理分别为 `com.example.lqinternalmatch` 与 `com.booster.default3v3ai`。逐文件核对源码、构建包和部署文件 SHA-256；唯一差异是顶层只有说明文字的 `__init__.py` 被构建器置空，部署与构建包一致。构建时源码尚未提交，最终代码可按清单核对。

证据目录：[run01](attacker-pass-margin-evidence/run01/)，包含 [身份清单](attacker-pass-margin-evidence/run01/identity.json)、构建时差异、Studio 配置、runner 日志、裁判采样和导出边界。

## 未得分原因与证据边界

- 裁判剩余 593.760 秒记录我方最后触球后出界，对方获得界外球；球出界位置约 (0.096, 4.638)。此前触球者为我方 1 号，回放中 3 号进入射门请求状态，但事件中没有确认 3 号接到该次球。直接证据是出界中断；预测接球目标与实际球路/接球动作不匹配是可能因素，不能仅靠动作请求确定具体执行误差来源。
- 剩余 578.530 秒裁判记录我方 3 号触球；随后多帧出现 3 号传 1 号选择。到剩余 567.188 秒，球在约 (2.060, 4.640) 出界，再次判给对方界外球。在此区间没有裁判确认我方 1 号触球。因此没有验证接球后第二脚射门；不能把“两段成功率乘积”当作已实现的传射。
- 最后阶段，3 号在直射与传球之间多次切换；剩余 543.002 秒我方 2 号触球，540.262 秒对方 1 号触球。短测结束前无进球。仅能确认阈值选择和力度指令接入，未形成可确认的队友接球后得分链路。
- 模型没有接球控制、转身准备和实际力度到球速的标定；接球者不受两脚计划约束。上述因素可能影响转化，但本次没有对照实验，不能指定单一原因，也不自动修改战术或追加比赛。
