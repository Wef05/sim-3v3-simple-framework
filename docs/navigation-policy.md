# 行走与预测避障实现

日期：2026-10-31。范围：策略侧行走、队内让行、踢球交接前的球门结构检查。保持既有角色分配、进攻目标和守门战术。

## 分层与数据流

1. `player.coordinate` 从完整角色/意图快照设置移动优先级、对手避让模式和球的排斥范围，不计算底盘速度。
2. `actions.execute` 更新一次共享 `MotionTracker`，建立本帧 `NavigationFrame`。所有球员依据同一份观测规划，不边决策边执行。
3. 按优先级从高到低调用 `MotionController.plan_walk`，将选出的速度保留给后续队友检查。规划阶段无 SDK 调用。
4. 复核整队最终指令之间的预测碰撞：先停止低优先级移动；仍冲突则停止高优先级移动，并重新核对其余组合。
5. 完成规划后逐个下发。原有罚下、摔倒、定位缺失和模式检查仍在最终执行入口生效。

`MoveIntent` 新增 `motion_priority`、`opponent_mode`、`ball_keepout`。原有 `avoid_robots` 留作调用兼容，已不能关闭机器人身体防碰撞。`avoid_ball` 仍表达是否需要避免主动触球。

## 通行优先级

| 场景 | 优先级 | 处理 |
|---|---:|---|
| 守门限时封堵 | 100 | 保持原定直线目标，不自动绕路 |
| 进攻追球、守门出球准备 | 80 | 优先获得通行空间 |
| 常规守门站位 | 60 | 维持面向球的全向移动 |
| 自由人/支援站位 | 20 | 对已规划的高优先级轨迹额外留空 |
| 准备阵型等普通移动 | 10 | 同级按球员编号从小到大排序 |

高优先级仍检查低优先级队友的当前位置、观测运动以及可能停下的情况；低优先级另外检查高优先级已经选出的速度。额外让行余量 0.10 m 只用于优先级更高（同级编号更小）的预约；低优先级预约仍检查身体及制动碰撞。静止、转向、出球中的队友也保留占地。没有强行把静止球员移开的逻辑。

紧急直线封堵（优先级至少 100）的移动走廊若与队友踢球接近球的走廊冲突，执行层先取消低优先级队友本帧踢球并停车，再下发封堵动作。普通走位不触发该取消。取消不会豁免实体、观测速度或制动检查，也不表示 SDK 已瞬时停止。看板以 `kick_yield` 与阻挡者优先级记录该执行覆盖。

优先级不是碰撞豁免，也不是整个场地路径的长期预约；它只约束本帧短期预测窗口。优先级由当前职责决定，同级编号稳定，避免依赖球员遍历顺序。

## 按场景处理对手和球

| 场景 | 对手 | 球 |
|---|---|---|
| 进攻追球 | `contest`：保留身体碰撞间距，去掉额外战术距离 | 可主动接近/触球 |
| 守门封堵、出球准备 | `contest` | 允许接近；出球准备的绕球分段仍由守门策略给出 |
| 常规守门、自由人和普通站位 | `avoid`：额外留 0.15 m | 按已有意图避球，并检查未来球轨迹 |
| 对方开球、定位球保护阶段 | `avoid` | 强制避球，排斥半径至少为场地 `circle_radius` |

这里的重开保护距离是可调整的策略设置，不是对赛事规则的独立核验。未来增加接球角色时，可通过 `avoid_ball=False` 请求主动接球；本次没有新增传球接应状态机。

## 静态几何与路径

- 两侧门柱、侧网、后网始终存在，不能被追球模式关闭。沿用已提供的球网矩形覆盖圆模型。
- 自身规划半径为 0.25 m；距离检测必须加上障碍物半径。
- A* 常规栅格约为 0.35 m，八方向搜索；以预计秒数计价，非全向模式将入射方向纳入搜索状态。每条边检查完整线段，不允许斜向切过障碍。目标点不再豁免障碍检查。
- 实际起点通过经过碰撞检查的连线接入网格，不能把机器人瞬移到量化后的起点。
- 场地边线不作为导航障碍。A* 搜索覆盖场地矩形、实际起点和原始目标，向四周再扩展 1.5 m；每轴最多 80 格，远距离时增大格距。搜索窗口只控制计算规模，不能保证找到窗口外的长绕路，粗网格也可能漏掉窄通道；无路仍进入动态安全层校验的局部候选。
- 优先使用安全直线；A* 路径只在整条快捷连线安全时平滑。
- 前视距离 0.9 m 按路径累计，遇到不可直视的拐角停留在前一可见点，避免跨弯切角。
- 普通和 `direct_path` 目标都保留上层原始坐标，允许在场外。直线模式只在实体/场景障碍阻挡时停止，不因越过边线拒绝目标。`clamp_target` 只为上层自动回场选择内缩 0.25 m 的目标，不用于行走目标处理或全局路径规划。
- 已经进入膨胀余量时，允许距离单调增大的脱离动作，不允许继续挤入障碍。

A* 的安全余量为自身半径之外再加 0.10 m；最终速度检查的安全余量为 0.04 m。前者帮助路线远离障碍，后者允许安全地通过较窄空间。A* 无路时允许尝试经动态安全层验证的局部速度；所有候选不安全则停车。

## 当前与预测碰撞检查

`MotionTracker` 按观测的仿真时间差估计队友和对手速度。重复观测不更新速度；时钟回退、丢失观测、不合理跳变或超过 0.5 s 的观测年龄使速度估计失效并退回静态占位。球沿用已有 `BallMotion` 的减速预测。

局部规划检查未来 0.9 s：

- 模型包含 0.10 s 反应时间和 0.25 s 速度过渡时间，检查零指令下可能残留的运动。
- 用 0.10 s 分段近似转向和球的非线性轨迹；每段计算相对运动线段的最近距离，不只比较离散端点。
- 比较目标方向附近的偏转方向与 100%、65%、35%、15% 速度。首选动作安全时直接采用，发生阻挡才扩大搜索。
- 保留近距/守门全向移动、远距先转向后前进的控制方式；局部方向使用世界坐标记忆，过期时间 0.6 s，按预计改向时间比较候选。
- 机器人中心在导航安全边界外时，使用固定朝向的全向平移，避免先转后走在受阻入口反复换向；进入安全边界后恢复普通朝向控制。预测碰撞与队内复核仍生效。
- 速度检查始终包含门柱/球网、队友和对手；球按场景加入。不再检查场地边界，场内出场、场外向外和跨线绕行均允许；反应/制动残余轨迹仍参与实体碰撞检查，不产生 `field_boundary` 受阻原因。
- `direct_path` 不选择其他绕行方向，但动态障碍可能使它减速或停止；到达时间仍需以实际执行为准。

速度未知时的静态占位不等于确定对方静止；短期预测也无法保证避免对方突然变向、定位误差或制动超出模型的碰撞。`stop_conflict` 表示停车预测仍可能被碰到，不能把“已发停止”解释成风险已消失。

## 场外回场

READY 仍使用编号对应的阵型位置。PLAYING 且允许行动时，未受罚、未倒地、行走模式已就绪并有有效位置的机器人，如果中心在实际场地矩形外，则暂时以 `return_to_field` 行为走向最近的场内安全点；该动作不依赖球观测，也适用于开球等待者。中心入场后恢复角色行为，已有球与对手保护距离仍由协调层附加。该逻辑不保证没有可行路径时强行入场。

暂停标志优先于 READY/PLAYING，INITIAL、SET、FINISHED、无裁判状态及受罚时不触发回场。执行前再次核对处罚、倒地、模式及位置。未知或非有限位置不触发回场。相关回归见 `checks/test_field_reentry.py`；离线积分不等于真实步态验证。

## 踢球与观测

踢球控制器在 SDK 内部接管步伐。本次增加交接前检查：机器人到球的接近线段若穿过门柱/球网，则取消踢球并停车。该检查没有获取 SDK 内部真实脚步轨迹，因此不能宣称完成了踢球阶段全程路径验证。

遥测每名球员增加 `navigation`，包括优先级、策略、目标/有效目标、路径/引导点、速度和受阻原因。主要状态包括 `moving`、`turning`、`avoiding`、`yielding`、`blocked`、`blocked_direct`、`team_conflict_stop`、`kick_approach_blocked`。字段保存在现有遥测/回放数据中，本次未新增看板控件。

## 2026-11-01：耗时计价与路线保持

变更范围仅限现有导航链路及对应看板。详细验证与未完成的仿真见 [实验报告](navigation-time-stability-report.md)。

- 非全向路径计价：前进时间 + 超出 `TURN_THRESHOLD` 的转角 / 转速；每个转折更新入射朝向。全向路径按身体坐标的前后、侧向位移构造椭圆速度模型。路径平滑仅接受安全且预计总耗时不增加的快捷连线。
- 初值沿用守门能力估计：前进 0.75 m/s、侧移 0.45 m/s、后退 0.40 m/s、转身 1.0 rad/s。参数 `NAV_*_SPEED_*` 是模型估计，不改变 SDK 指令上限；不包含精确步态、加速及近终点减速，预计到达时间不是承诺。
- 每名控制器只保留当前任务的剩余路径。通过最近投影裁剪已走路段；复核时采用现有安全层 0.04 m 余量，新路线仍采用规划层 0.10 m 余量。旧路线局部受阻时尝试安全连接原拐点，最多保留 64 个修复拐点；不安全或不可修复时允许重规划。动态轨迹预测和队内最终复核照常执行。
- 新路线必须比安全的旧路线或修复路线预计至少快 0.35 s 才替换，避免小幅移动导致两侧路线轮流占优。路线已不安全时不受此门槛限制。
- 局部候选按同一时间模型、沿路线的有效进度及改向开销计价；记忆世界方向并重新验算其安全性，绕行侧相对最终目标定义。
- 到达、停止/踢球/非移动动作、失去位置、摔倒/受罚/退出行走、比赛阶段变化、时钟回退或帧间隔超过 0.6 s 时清除记忆。目标相对本任务锚点累计变化超过 0.5 m、朝向要求显著变化或导航模式/约束变化也重置。`direct_path` 保持直线约束。
- 遥测新增 `estimated_time_s`、`candidate_time_s`、`previous_time_s`、`switch_margin_s`、`route_reason` 和 `direction_held`。看板兼容现有 `state/speed` 与旧版 `reason/velocity`；显示预计耗时、保留/更快/受阻换路原因及方向保持状态。旧回放缺少新字段时不伪造数值。
