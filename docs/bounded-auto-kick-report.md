# 自动踢球交接：基于 MAIN #9 的宽限退出方案

## 范围与实现

按用户批准，在 MAIN #9（fa90cfc8）的场外导航行为上实现新版方案 1；方案 2 的新球路兜底和门柱脱困不实施。原有 `blocked_attack_target` 逻辑保留，不修改 SDK 内部控制器、角色分配或导航架构。

| 项目 | 当前行为 |
| --- | --- |
| 进入 | 距球 ≤0.65 m，朝向误差 ≤25°，球后 0.35 m 准备点误差 ≤0.20 m，球在身体前方；观测和实体安全检查通过 |
| 距离退出 | >1.50 m 持续 0.30 仿真秒 |
| 朝向退出 | >70° 持续 0.30 仿真秒 |
| 身后球退出 | 球在身后持续 0.50 仿真秒 |
| 单次预算 / 冷却 | 最多 5.0 仿真秒，退出后冷却 0.5 仿真秒 |
| 即时退出 | 无效观测、不可用目标、危险路线、角色/阶段变化、时钟回退或执行拒绝，不等待宽限 |

三个超限计时器独立；恢复正常即清零，取消和阶段变化不会遗留计时。接管后不再要求机器人回到最初准备点。观测球位与延迟补偿球位均检查，观测年龄上限 0.25 s。

解决与 #9 的语义冲突：删除旧 `clamp_target` 依赖，不恢复强制回场；标线允许跨越，准备点保留真实坐标。门柱、球网、机器人仍阻挡，落在后网实体内的准备点提前停止；这不是新的脱困策略。

看板显示请求/后端接受、准备状态、5 秒预算、冷却、最近退出原因，以及每个退出宽限的条件和剩余时间。缺字段的旧回放显示未记录；后端接受不代表实际出脚或触球。

### 失分原因分析

裁判事件 **28** 在 now=102.798、剩余 **572.954 s** 确认对手得分。

- 帧 3104（now=99.016）：球约 (-4.596,-0.470)，2 号位于 (-6.289,-0.276)，预测门线 y≈-0.502。
- 帧 3148（now=100.976）：球仍近乎静止；预测门线改为 y≈+0.951，2 号位置 (-6.584,-0.174) 并向上调整。1 号距球仍超过 2 m，3 号仍受罚。
- 帧 3172（now=101.996）：实际球到 (-5.688,-0.462)，2 号位于 (-6.692,+0.029)，改为紧急封堵；预测落点 y≈-0.450。
- 帧 3184（now=102.612）：球 (-6.836,-0.450)，2 号 (-6.715,-0.050)，预计到门时间只剩约 0.096 s。随后球越过门线。
- 直接证据是预判方向改变、实际球路偏下、临门时守门员仍有横向距离，且另外两名球员未在窗口内拦住。合理推断：预判调整后的回补时间不足，加上 3 号受罚减员，削弱了防守。缺少全部物理接触和执行反馈，不能确定单一原因；本次没有修改守门或定位球防守逻辑。

## 风险与未验证范围

1. 退出明显放宽，底层单次接管上限由旧方案的 1.2 s 增至 5 s；可避免正常踢球被频繁打断，也可能延长无效接管。参数尚未做多场验证。
2. 宽限和预算按仿真时间检查；实际取消受控制帧间隔及 SDK 停止调用影响，不是物理瞬时停止保证。
3. 本场没有宽限或超时事件，也未复现原门柱卡住状态。1 号只有一个 PLAYING 采样点距门柱小于 1 m（最小 0.984 m），3 号最小 3.798 m。不能声明“球员不会再卡门柱”已通过完整实测验收。
4. 准备点被球网占据时仍可能停等；新脱困方案明确未实施。定位球干扰、接球出界、守门预判偏移是本场观察到的后续调查项，未擅自修复。
5. 全量测试仍受既有守门回放样例缺失影响。已完成当前批准方案、定向验证和一次短时仿真，原始门柱问题的全面效果仍待专项复现验证。
