# 按防守站位选择射门角度

普通进攻和点球的默认射门不再固定瞄准门中心。`Player.shot_target()` 在对方门线上取 21 个候选点，距门柱留出 0.25 米，计算球到每个点的线段与前方对手、队友的最小净空。净空扣除对应机器人半径，并在 1.2 米封顶；分数再略微偏好中央，避免无人遮挡时无意义地贴门柱射门。

优先选择净空较大的方向。旧目标的分数与最优目标相差不超过 0.08 时保持旧目标，降低微小位置变化引起的左右抖动。所有线路均受阻时仍选择相对较好的门内目标，不保证一定能够绕过防守者。

`attack()` 的球后接近位置和实际出球使用同一个目标。显式指定 `attack(target)` 时尊重该目标；定位球 `pass_to(target, 1)` 仍向指定接应点以参数 1 出球。守门员解围/传球保留独立逻辑，普通射门力度保留原配置。

沿用项目正 x 方向进攻的坐标约定，仅评估当前帧几何遮挡，不预测对手移动、球速或扑救范围。球不可见或已经越过对方门线时不提交默认射门。

验证：73 项本地单元测试通过，其中 11 项新增测试覆盖中路封堵、左右防守变化、队友遮挡、微小抖动、实际身体坐标出球、球后接近方向、显式目标及传球保持不变等。尚未进行实际仿真比赛验证。

## 右脚固定偏角补偿

根据用户仿真观察，右脚出球向左偏 5°。`src/param.py` 的 `KICK_LEFT_BIAS_DEG = 5.0` 表示这个观测偏差；最终身体坐标指令为 `normalize_angle(目标方向 - 身体朝向 - radians(5))`，即向右补偿 5°。设为 0 可关闭，负值用于补偿向右偏。

补偿统一放在 `Player.kick()` 最终调用后端之前，适用于射门、定位球传球及守门员出球；不修改战术目标、球的身体坐标或力度，定位球传球力度仍为 1。重复提交指令不会累计偏移。可视化目标仍表示预期球路目标。

本次全套 91 项单元测试通过，覆盖补偿方向、不同身体朝向、跨越 ±π 的归一化、重复调用、关闭补偿及既有动作回归。补偿量依据用户观测设置，尚未重新运行仿真验证实际落点。
