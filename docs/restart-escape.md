## 问题与实现

原剧本只保证最终防守站位合法。复现场景：球 `(0,0)`，球员 `(0.3,0)`、朝向 π，目标 `(-2.2,0)`。直线会靠近球，A* 起点附近没有合法格点，返回 `no_route`；局部导航给出零平移、仅转向的指令。复现只证明导航风险，不把它当作某场判罚的完整归因。

新增 `src/utils/restart_escape.py`，由 `Player.decide` 在普通角色行为之前调用：

- 仅敌方 PLAYING 开球或定位球限制期间、可行动球员进入；不覆盖罚下、倒地、SET 或停止要求。守门员与两名外场球员都适用。
- 保持项目原保护半径 `max(circle_radius, 1.65)` 米。触发/释放边界增加机器人半径和导航膨胀余量，默认为 2.0 米；与 A* 边界一致，避免合法绕圈路线反复触发撤离。
- 候选为当前径向及 72 个均匀方向的圈外出口。目标默认距球 2.15 米，到达误差 0.03 米；全段只允许远离球，复用导航的球、队友、对手、门柱及球网检查。
- 优先选择场内最短可直达出口，使用全向、保持当前朝向的移动，优先级 110，保留执行层动态碰撞及队友预约。没有可行出口时停车并标记受阻，不使用穿越障碍的兜底。
- 若边线附近无可直达的场内出口，允许临时向场外撤离并标记 `escape_outside`。这是避免场界与远离球条件互锁的选择，不保证满足其他所有位置规则，需实测。
- 每帧根据当前观测重算，不缓存球位或撤离目标；球缺失/无效时不伪造位置。退出后恢复原剧本，进入撤离时清理原门将出球计划及剧本站位记忆。
- 门将与外场避球半径统一使用至少 1.65 米。看板动作包含 `escape` / `escape_outside` / `escape_blocked`，门将卡片增加对应中文说明。

没有修改公共意图格式、普通比赛路径算法或裁判阶段解除条件。目标可行与指令非零不等于机器人实测已完成撤离。
