# 开局回场与接球候选修复

任务 worktree：`/Users/limingzhe/.codex/worktrees/pass-coordination/sim-3v3-simple-framework`；分支 `codex/pass-coordination`，基线 `420c75f`。本轮按批准方案实施；历史无效尝试保留在 `receive-pose-evidence`，本轮证据独立保存在 `opening-repair-evidence`。

## 原因和修复

1. 历史帧 534004 的三名球员出生在 y≈5 m，导航场界为 y≤4.25 m。观测存在约 2–3×10⁻⁵ m/s 向外漂移，轨迹反应段与新指令无关，原判定却因此拒绝所有向内指令。改为相对起点的有界漂移预算：2 mm 噪声加反应/制动位移，最大 0.12 m；禁止向外命令、要求运动命令最终向内，保留机器人、球及球门碰撞校验。执行层先低速回到场内 0.12 m，再执行 READY 战术点；阶段停止和时钟重置清理状态。
2. 原传球几何筛选重复做时间否决；新姿态模型把准备、稳定接球、球后调整和射门准备全部作为硬争抢窗口，初始准备太远导致全拒绝。现在几何通道与统一争抢模型分离；稳定接球仍是硬条件，接球后进攻余量用于排序，球后路径和实际首次踢球姿态保护仍必须通过。
3. 当前裁判确认：对手开球前留在己方半场、中圈外，首次本方触球即解除保护。模型使用运动圆、合法半场、中圈约束的保守可达距离下界，允许对手在准备期间移动；倒计时扣除整数误差和观测年龄，过期或对手已违规时不用保护。不是假定对手静止。
4. 转向和全向移动按并行执行估计，准备时间仍保留 0.2 s 就绪稳定及 0.15 s 控制延迟。接球朝向最多向进攻方向偏 30°；READY 的 1/3 号朝向对应开球配合。上边线附近新增向左较多、向上较少的候选。
5. 无正式候选时，仅在“到位后保留最低确认延迟仍可接球”的候选中生成预走位。双方先移动，反复检查同一个接球点、等待点及朝向；此时没有传球承诺，也不能产生踢球。实际准备预算通过后才建立正式计划，仍需双方多帧就绪。预走位 8 s 超时失效，比赛阶段切换清理；全无安全候选时 3 号守住开局锚点。

## 实验计划和验收

仅进行一次有效的 60 s 验证：核验源码/构建包/部署摘要，官方重置后等待至少 60 s；核验 READY 运动及首次 PLAYING 的双方三人位置、我方距 READY 点不超过 0.8 m、无倒地/处罚。裁判固定 600 s 赛制，主计时消耗至少 60 s 后主动结束，不称自然完赛。保留看板历史并按帧边界导出。无效场外出生开局仅按技能恢复规则保留证据后重置；不根据战术效果自动加赛。
