# 守门员出球规则（2026-11-02）

本说明对应 `src/utils/goalkeeper.py`，是源码行为说明，不是仿真效果结论。2 号固定守门、READY 站位和角色可用性规则不变。

## 决策顺序

1. 无有效比赛状态或自身定位时停止；球观测超过 0.25 秒时回小禁区中心。
2. 对方重启限制期间不主动出球，沿用受限站位。
3. 球在己方小禁区内且可直接出脚时，优先沿当前朝向解围，包括已识别入门威胁的可触及球。
4. 当前朝向射线会打进己方球门时，禁止该方向，改选可直接执行的边线方向。没有直接可执行的边线方向时，只允许通过防守检查的原地转向或最大 0.25 米准备位移，不能为了遵守“直接踢”而朝己方门内踢。
5. 无法直接处理入门威胁时，沿用原来的身体封堵；有入门威胁时不为出球调整位置。
6. 非小禁区的门前球按“队友、边线、当前朝向”分级选择：同级先找可直接出脚的目标，其次才考虑安全调整。已开始且仍可执行的出脚可保持原目标，避免逐帧重新选目标打断。
7. 没有可执行出球或安全调整时，沿用射线预判与常规站位。

## 范围与直接出脚

己方球门位于负 X 方向。小禁区按实际场地 `goal_area_length/width` 判断；当前14×9米场地上为 x∈[-7,-6]、|y|≤2。其他门前处理范围仍只扩至小禁区前沿外0.6米，人球距离不超过1.8米，不扩大出击区域。

直接出脚要求人球距离0.06～0.60米、球相对身体朝向偏差不超过0.75rad、踢球方向相对身体朝向偏差不超过0.65rad。已开始的非近门出脚允许人球距离至0.85米。以上都是待实测几何初值，不表示SDK一定完成触球。

取消旧的“球速必须≤0.65m/s”“比对手更近0.12米”“队友先到就让球”等统一门槛。新鲜球位但速度尚未知时，允许直接出脚，不允许预测性调整。直接出脚不要求退到标准球后点。近门出脚与当前朝向兜底接受争球/球路被截风险，不因远端球路出现机器人就放弃。

防乌龙检查使用从球出发的无限射线，分别检查战术方向及执行层右脚补偿后的方向，门口按球半径扩张；门柱/球网检查也分别检查这两个方向。检查不能涵盖未来碰撞或反弹乌龙。

## 目标与调整

队友候选必须可接球、在场内、距离0.5～6米，不再要求在球前方0.75米。初选队友/非近门边线目标仍检查球路与机器人实体占位；3号只作为同角度时的偏好。

边线候选为上下两条边线外0.2米，纵向取当前球位及向前1.5、3米的位置，限制在两端门线内0.35米，按所需转角排序。边线出界是有意的解围取舍，不把球门线当边线。

调整先尝试原地转向，再尝试球后0.35米的准备位置。必须满足：

- 对手位置已知；预计移动、转向、0.6秒出脚准备以及0.15秒反应余量之和，早于对手最早触球估计。
- 对手时间取直达下界和共享威胁器结果的较小值；不使用此前额外0.5秒争抢优势门槛。
- 准备期间球预测位移不超过0.15米。
- 分段路径不穿球、机器人、门结构；近门逃逸的最终点与中间点均距当前位置不超过0.25米。
- 对球门口取9条射线，整条准备路线不得放弃当前身体已经覆盖的采样射线，不假定其他队友会持续补位。

这是一种保守近似，并非“保证对手无法射门”：不预测对手未来出脚变化和所有碰撞，身体覆盖与移动耗时均依赖待标定模型。

## 出脚保持、执行与观测

踢球请求不会因对手更近或远处通道风险上升而立即取消。新鲜度、比赛限制、门结构、防乌龙、可踢脚位、接球队友失效/漂移仍会使计划失效。近门当前朝向每帧重算，非近门已开始的可执行目标保持；换目标不重置同一段踢球计时。总请求时间上限1.2秒，超时冷却0.5秒；离开守门角色、停止、时间回退仍清理记忆。

执行层现有起身/罚下/模式检查及踢球接近门结构检查保留；SDK自身踢球挪步并无可验证的完整路径，本改动不声称可杜绝接触。普通移动、身体封堵继续使用现有导航安全层；本次不改变全队让路机制。

看板新增 `guard:direct_clear` 与 `outlet_mode` 解释；保留旧回放标签兼容。踢球标记始终只是请求，不等于实际触球。
