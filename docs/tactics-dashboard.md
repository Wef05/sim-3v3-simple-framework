# 自动踢球交接状态

球员卡片显示 `kick_control`（执行请求、后端接受、阻止、失败、取消失败）和 `auto_kick`（接近、对齐、请求、冷却、受阻）。计时使用仿真时间，从首次请求意图开始；后端接受不表示底层已经出脚或触球。旧回放缺少字段时显示未记录，不补造状态。守门员显示独立清球策略。

普通进攻的进入条件：距离不超过 0.65 米、朝向误差不超过 25°、真实球后准备点误差不超过 0.20 米、球在身体前方，观测和实体安全检查通过。继承 MAIN #9：标线可以跨越，准备点可以在场外，不裁剪目标，不强制回场；门柱、球网和机器人仍是实体障碍。

接管后不再要求位于启动准备点。距离超过 1.50 米或朝向误差超过 70°，各自持续 0.30 仿真秒才退出；球在身后持续 0.50 仿真秒才退出。三个宽限独立计时，恢复正常即清零。看板逐项显示超限原因及剩余宽限，退出后清除宽限显示。角色/阶段变化、时钟回退、无效观测、目标不可用、实体危险和执行拒绝不会等待宽限。

单次请求最多 5.0 仿真秒，到期后首个控制帧取消；退出后冷却 0.5 仿真秒。看板显示已持续时间、剩余预算、冷却及最近退出原因、朝向/站位误差和准备点。实际停止受帧间隔和 SDK 调用影响。这些是待实测参数，不代表 SDK 的物理出脚阈值。本次不新增球路受阻兜底或门柱脱困。
